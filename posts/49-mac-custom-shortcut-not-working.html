Mac Custom Keyboard Shortcut Not Working? Check Menu Names and Conflicts

Published on October 26, 2026 • Updated on October 26, 2026 • By Tweaknook Editorial

A custom keyboard shortcut on a Mac may appear in System Settings yet do nothing in the intended app. Before assigning a different combination, check two things: does the app have the exact menu command you entered, and is another shortcut already using those keys? A menu-title mismatch and a key conflict require different fixes. Changing random keyboard settings will not reliably solve both.

This guide is for shortcuts added through System Settings → Keyboard → Keyboard Shortcuts → App Shortcuts. It does not cover automations created in the Shortcuts app, arbitrary macros, or a website's own keyboard settings. These mechanisms are not interchangeable.

Which failure are you seeing?

What happensFirst thing to inspectWhat would distinguish the cause
The shortcut is listed, but the menu action never runs.Menu title and chosen applicationThe command must exist in that app's menus and its name must match.
Spotlight or another macOS action opens instead.System-wide shortcut ownershipThe key combination may already belong to macOS.
It works in one app, but not a second app.App-specific versus All Applications scopeThe two apps may have different menu commands or assignments.
The shortcut only fails with F1–F12 or on another keyboard.Fn/Globe behavior and input sourceThe physical keys or keyboard layout may not be producing the intended combination.
The shortcut works sometimes, depending on the document.Whether the menu command is enabledThe app may disable that command in the current state.

The last row is a useful diagnostic distinction: a gray, unavailable menu command is an app-state problem, not proof that another shortcut has intercepted the keys.

Start with the application's menu bar

Open the actual app and put it in front. Use the mouse to find the command in the macOS menu bar. Can you select it? Does clicking it perform the action? If not, stop troubleshooting the keyboard shortcut and investigate the app's command or document state first.

If the menu action works, record its exact wording, punctuation, and location. A command named Export… is not necessarily the same as Export as PDF…; an ellipsis is not decorative when defining an App Shortcut. Apple specifically requires the menu title entered in App Shortcuts to match the app's menu command, including relevant punctuation and submenu structure.

For a nested command, follow Apple's notation rules for menu paths instead of guessing from the final submenu label. Apple's example for a File-menu PDF export uses the menu path format File->Export as PDF…. Use it only if your app actually has that menu path; it is an example of syntax, not a claim that every app includes that command. Apple's guidance explains how to represent arrow separators and ellipses in the field, including typing three periods without spaces for an ellipsis.

Recreate only the incorrect assignment

  1. Open Apple menu → System Settings → Keyboard → Keyboard Shortcuts → App Shortcuts.
  2. Select the custom shortcut and check its Application and Menu Title. If it is intended for one program, select that program rather than All Applications.
  3. Correct the menu title to match the app's visible command. Keep the command's exact spelling and punctuation; recheck after an app update or localization change.
  4. Enter the intended key combination and save it. If the settings screen shows an existing assignment or warning, resolve that collision instead of repeating the same shortcut.
  5. Return to the app and try the command with the app active and the menu item enabled.

Use All Applications only for a menu command you genuinely expect to exist with the same name across apps. It will not make an absent menu command appear. Apple notes that App Shortcuts are for existing menu commands, not a general way to launch apps or perform arbitrary tasks.

Before changing the keys, identify who owns them

A familiar combination can already be taken. For example, Command + Space is documented as a macOS Spotlight shortcut. A custom app assignment with those same keys is a poor first candidate unless you understand and deliberately change the existing behavior. Check System Settings → Keyboard → Keyboard Shortcuts, particularly the system categories relevant to your combination. Apple documents warning indicators for conflicts and allows you to change the affected assignment. Apple's conflict-resolution instructions explain the procedure.

When several combinations are under consideration, HotkeyRadar's keyboard shortcut checker can compare a candidate with its documented macOS, Safari, Chrome, and other supported browser records. Choose macOS and the browser or system scope you actually need. It also lets you add shortcuts from your own applications to a locally saved reference library and check them later.

What the checker cannot do: it cannot read the menu titles in your installed apps, discover every third-party hotkey or remapper, inspect your current keyboard layout, or guarantee that a combination works. A result with no known match is a screening result, not permission to skip an actual test. The built-in vendor-reference data has its own published review date, so confirm the current behavior against Apple and the app's current menu.

Two examples that look similar but need different repairs

Case A — incorrect menu title (illustrative). A person wants a shortcut for a menu command displayed as Export as PDF…, but types Export to PDF into App Shortcuts. Changing the key combination does not repair the missing command match. The useful test is to activate that exact menu item using the mouse, then correct the menu title and submenu notation as needed. No particular keyboard combination is assumed to be free.

Case B — reserved combination (illustrative). A custom action is assigned to Command + Space, and pressing it activates Spotlight. That is consistent with the documented system shortcut. The next action is to choose a different candidate or intentionally change the conflicting macOS assignment, then verify both Spotlight and the custom app command. The fact that the menu title is perfect would not by itself resolve this collision.

These are diagnostic examples, not claims of a physical Mac test. The important distinction is text lookup versus key ownership. A troubleshooting step that addresses one does not automatically address the other.

If it still fails, use this short second pass

  • Check the input source: symbols and physical key locations can change with keyboard layouts. Read the app's menu bar and, if necessary, use Keyboard Viewer to determine which keys the Mac is receiving. Apple notes that shortcut behavior can vary by language and layout.
  • Check Fn and Globe: combinations involving function keys may require Fn or Globe depending on keyboard hardware and settings. Do not treat every function-key failure as a conflict.
  • Check app version and availability: some apps do not support App Shortcuts for a particular command, and menus can change between releases. If the command is dimmed, put the app into a state where it is available before testing.
  • Check the target app: a shortcut created for one app does not automatically govern a second app with a similar menu. Reconfirm the application selection.
  • Check user-installed remappers separately: a keyboard utility or third-party app can handle combinations not included in a browser-based reference data set. Review its settings directly; do not infer them from HotkeyRadar.

Confirm the change without creating a new problem

Keep a simple record of the application, exact menu title, previous combination, proposed combination, and observed result. This is especially useful when several apps use overlapping commands. The test should be small and reversible:

  1. Click the original app menu item and note what a successful operation looks like.
  2. Run the replacement keyboard shortcut while the same menu item is enabled.
  3. Open a second app or a different document state and verify the shortcut does not trigger an unwanted global command.
  4. Check whether the displaced original shortcut still behaves as intended. Restore it if the new binding creates a worse conflict.

If the assignment fails even with a verified menu title, app selection, active command, and non-conflicting candidate, consult the app developer's shortcut documentation. Apple's App Shortcuts feature does not override every application's custom keyboard handler.

For the distinct problem of shortcuts that fail specifically inside a Chrome-based web app, see the Chrome web-app shortcut diagnostic. If you are choosing one new combination before configuring any app, the broader shortcut conflict screening guide covers system, browser, and user-library scopes.
