VS Code Ctrl+Shift+P Not Working? Restore the Command Palette

Published on October 29, 2026 • Updated on October 29, 2026 • By Tweaknook Editorial

If Ctrl+Shift+P does nothing in VS Code, try F1 first. If the Command Palette opens with F1 but not with Ctrl+Shift+P, the feature is probably available; the key combination is not reaching the same command. The next question is whether you are in the desktop editor or in vscode.dev inside a browser. Those cases have different remedies.

On macOS, the default Command Palette shortcut is Shift + Command + P, not Ctrl+Shift+P. The checks below use Windows/Linux keys unless otherwise stated. Don't reset the keyboard or reinstall VS Code before finding which layer handles the shortcut.

Try the command without its shortcut

Open View → Command Palette, or press F1 (on some laptops you may need an Fn key). Type a harmless command such as Preferences: Open Keyboard Shortcuts and confirm the palette responds. You have now separated access to the Command Palette from the keybinding that opens it.

Using VS Code in Firefox? The browser may own the keys

Microsoft explicitly documents that Ctrl+Shift+P cannot open the Command Palette in VS Code for the Web in Firefox because Firefox reserves the shortcut. Its documented workaround is F1. On macOS, the affected Command Palette combination is Shift + Command + P. Trying to rewrite VS Code's local desktop keybindings will not fix the browser's reserved shortcut on a web page.

This distinction matters if the same repository works in desktop VS Code but fails after opening vscode.dev or a browser-based Codespace. First verify which environment is visible in the address bar or app window. In a browser, click into the code editor and try F1. If it opens the palette, use that supported path instead of disabling browser security features or installing a keyboard remapper just to reclaim one shortcut.

If you're not in Firefox, don't assume the same cause. Browser, operating system, installed extensions, and the page's focus can affect shortcuts in different ways. Compare the same action via F1 and the intended keys in your actual browser rather than applying a Firefox-specific fix elsewhere.

On the desktop, let VS Code report the keys it received

VS Code includes a built-in diagnostic specifically for this. It is more useful than guessing which extension took over the shortcut.

  1. Press F1 to open the palette. Run Developer: Toggle Keyboard Shortcuts Troubleshooting.
  2. With the Output panel visible, focus the editor and press Ctrl + Shift + P once. On a Mac, press Shift + Command + P.
  3. Read the new keyboard-shortcut log entry. Look for the key combination VS Code received and the command or rule it resolved. The exact messages can differ by version.
  4. Repeat in the UI location where the shortcut normally fails, then compare. A different active focus can change which conditional rule is eligible.
  5. Toggle the troubleshooting command off when finished; no global keyboard settings need to change during this inspection.

How to interpret it: if VS Code logs a different key than the one you intended, investigate keyboard layout, hardware, modifier state, or a remapper. If it logs the intended key but picks another action, inspect the editor's keybinding rules. If there is no corresponding log event, the keystroke may have been consumed outside VS Code; that is a clue, not conclusive identification of the culprit. Compare with a second known shortcut and test with the same focus before assigning blame.

Find the competing binding instead of wiping all shortcuts

Open Preferences: Open Keyboard Shortcuts from F1. Use the keyboard recording control in the Shortcuts editor to search for the physical combination, and inspect every matching result. VS Code's Show Same Keybindings command is designed for this case.

Two rules can use the same keys without both being active: a rule's when expression controls its scope. The documentation explains that matching rules are evaluated in precedence order and that user-defined keybindings can override defaults. Check the action, the active context, and whether you deliberately changed a shortcut or installed an extension that added one. The correct repair may be to remove one obsolete override rather than choose a completely new global shortcut.

Before editing keybindings.json, save a copy of your current custom bindings. If the Shortcut editor shows an unintended user assignment, remove or restore that specific assignment and retry. Don't paste a guessed replacement JSON rule from a forum: it may work only in one editor context, break a second command, or introduce a syntax error.

A concrete example: two machines, two different fixes

Browser case (documented). A developer opens vscode.dev in Firefox and presses Ctrl+Shift+P. The Command Palette stays closed, while F1 opens it. That behavior fits Microsoft's documented Firefox reservation. The low-risk solution is to use F1 in the web editor, not to reset VS Code's desktop profile.

Desktop case (illustrative). The palette works from the View menu, but Ctrl+Shift+P runs an unrelated extension command. The troubleshooting log reports that unrelated command for the exact keys. The useful next step is to find the competing binding and review its when condition or override. Changing browser permissions would not address a binding already resolved inside the desktop editor.

Verify the repair with the same task that failed

Return focus to the original VS Code editor or browser tab. Open the Command Palette using the intended shortcut twice and confirm it shows the list of commands rather than a browser action or another editor command. If you changed a user binding, check a second editor context and confirm the previous command still has a usable shortcut or menu path. If the result is worse, restore the copied bindings and use F1 while you investigate.

The key diagnostic is simple: F1 tells you whether the palette is reachable; the shortcut log and environment tell you who has the keys. Fix the layer that failed, not every keyboard setting on the machine.
